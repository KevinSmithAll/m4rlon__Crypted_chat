# Безопасный чат на Python с использованием RSA и Fernet
Этот проект представляет собой реализацию защищенного чата на языке Python с использованием сокетов. Для обеспечения безопасности применяются два основных криптоалгоритма: RSA для обмена ключами и Fernet для симметричного шифрования передаваемых данных.

## Как работает система?
##### Генерация ключей:
Клиент создает пару закрытых и открытых ключей RSA.
Открытый ключ отправляется на сервер.
##### Создание сеансового ключа:
Сервер генерирует симметричный ключ с помощью алгоритма Fernet.
Этот ключ шифруется открытым ключом клиента и передается обратно.
##### Расшифровка и установка соединения:
Клиент расшифровывает симметричный ключ своим закрытым ключом RSA.
После этого устанавливается защищенное соединение с использованием симметричного шифрования.
## Преимущества решения
1) Высокая безопасность: комбинация асимметричного (RSA) и симметричного (Fernet) шифрования обеспечивает надежную защиту данных.
2) Скорость передачи данных: благодаря использованию симметричного шифрования передача данных осуществляется быстро.
3) Простая реализация: используется стандартная библиотека Python cryptography, что упрощает поддержку и развитие проекта.
## Рекомендации по улучшению
1) Размер ключа RSA: убедитесь, что размер ключа RSA составляет минимум 2048 бит для лучшей защиты.
2) Периодическое обновление ключей: рассмотрите возможность регулярного обновления симметричных ключей для повышения безопасности.
3) Цифровая подпись: добавьте цифровую подпись для подтверждения целостности и аутентичности сообщений.
4) Использование TLS/SSL: рассмотрите применение TLS/SSL для полного шифрования трафика и соблюдения стандартов безопасности.
5) Проверка сертификатов: включите проверку сертификатов для повышения доверия и безопасности.

# Принцип работы алгоритмов RSA и Fernet
## Алгоритм RSA
RSA — это асимметричный алгоритм шифрования, который основан на сложности факторизации больших чисел. Его суть заключается в использовании двух разных ключей: открытого и закрытого. Открытый ключ используется для шифрования данных, а закрытый — для их расшифровки.

### Основные шаги работы RSA:
1. Генерация ключей;
2. Отправка открытого ключа;
3. Шифрование данных;
4. Расшифровка данных;

## Важные моменты:
Размер ключа RSA влияет на уровень безопасности. Рекомендуется использовать ключи размером минимум 2048 бит.
RSA является относительно медленным по сравнению с симметричными алгоритмами, поэтому его используют только для обмена ключами.

## Алгоритм Fernet
Fernet — это высокоуровневый интерфейс для симметричного шифрования, реализованный в библиотеке cryptography. Он обеспечивает безопасность данных с помощью симметричного шифра (обычно AES) и гарантирует целостность данных с помощью MAC (Message Authentication Code).
### Основные шаги работы Fernet:
1) Генерация ключа:
- Сервер создает случайный симметричный ключ с помощью функции `Fernet.generate_key()`.
2) Шифрование данных:
- Данные шифруются с использованием симметричного ключа и алгоритма AES в режиме CBC.
- К зашифрованному сообщению добавляется MAC для проверки целостности.
3) Передача зашифрованных данных:
- Зашифрованный ключ Fernet отправляется клиенту.
4) Расшифровка данных:
- Клиент расшифровывает полученный ключ с помощью закрытого ключа RSA.
- Затем расшифровывает данные с использованием симметричного ключа Fernet.

### Важные моменты:
Fernet гарантирует целостность данных благодаря использованию MAC.
Этот алгоритм значительно быстрее RSA, что делает его идеальным выбором для шифрования большого объема данных.
# Итоговая схема взаимодействия
- Клиент генерирует пару ключей RSA и отправляет открытый ключ на сервер.
- Сервер генерирует симметричный ключ Fernet и шифрует его с помощью открытого ключа клиента.
- Клиент расшифровывает симметричный ключ с помощью своего закрытого ключа RSA.
- Все дальнейшие коммуникации происходят с использованием симметричного шифрования Fernet.
- Таким образом, сочетание RSA и Fernet позволяет создать безопасный канал связи с минимальными накладными расходами на шифрование данных.
